# DTD functional pullback: phase 1

Implements the user's 2026-11-13 direction as an independent pilot. Original 6c78fee and v5 states are preserved. Uses the frozen v5 asset loader, full visual parameter scope (not just 48 matrices), a fixed training-origin probe, disjoint optimizer and development IDs. This is **not** a matched replay of the old 3384/376 experiment: it uses the v5 development protocol and 32 fitting +32 held training images. Historical 0.00440 cannot be treated as a causal baseline.

After 36 AdamW warmup steps, the actual model is generated from a local window anchor and a candidate-derived basis. Every 12 steps, the pool contains previous basis axes plus three recent task gradients and AdamW candidates. Twice-reorthogonalized parameter vectors form V, capped at 16 (a resource budget). Real JVPs of `q=2sqrt(p)/sqrt(N)` give the FR response directly, without an extra Fisher weighting. Thin response SVD retains at most 8 directions above a relative 1e-3 threshold. Rank-capped observable directions are separately reported and are **not** called vertical.

At each of up to four CE coordinate rounds, the actual response matrix is recomputed at the current model; retained singular values define functional coordinates. Both functional and parameter increments are bounded. Exact FP32 decoded weights are used for fitting and the held-training CE gate. No new high-dimensional optimizer write occurs after warmup. Anchors reset at window boundaries; this does not prove a fixed globally low-dimensional model.

The basis is restricted-observable, **not** proven to be in ambient Im(J^T), and orthogonal responses are not semantic independence. VJP purification is not implemented. Near-null directions are only probe-local numerical candidates. `b=0`; no fiber or curvature update is active. A nonlinear residual cannot generally be canceled outside the reachable response span, and a sphere's normal curvature cannot be eliminated by an arbitrary tangent correction. No exact geodesic/fiber claims are made. The old tangent-collapse diagnosis is not assumed.

Full historical checkpoints every 8 steps contain current theta, local anchor/basis/coordinates, recent candidate banks, AdamW state, iteration/events and source/assets/probe identity. Resume strictly validates identity. Data batches and augmentations are deterministic by step. Hard interruption recovers the last committed checkpoint; later partial work is replayed. SIGTERM requests stop after the current step. PyTorch process allocation is capped at 35% of the A100 (other-job peaks are not under this process's control).

First 44 total attempts (36 warmup +8 horizontal) serve as an explicit real pilot. Only if at least one horizontal step is accepted does the launcher resume to 128 total attempts. These are pilot/midlength budgets, not convergence or semantic validation. 4 CPU algebra tests pass; A100 success must be established from actual logs, not this document.
