# 今晚的实际研究目标与执行边界

目标不是仅交付数学接口，而是从完整条件运动学习能够承载新功能需求的控制结构。结果可能不低维；不得为了满足目标人为截断维数。

## 任务组织

八任务为DTD、SUN397、Cars、EuroSAT、GTSRB、MNIST、RESISC45、SVHN。每次以一个任务为目标，联合保护其余七个，形成8个目标条件，不是56个独立一对一问题。

每任务保护项是其余任务逐样本平均Fisher之和，初期权重相同。全部共享同一视觉参数坐标和明确锁定的模型位置。八任务来自实际分类任务，不是八个控制模式。

## 不预设的东西

不设置耦合块数量、块大小、支持候选名单、最终控制维数或最大模式数。不按前K个谱方向、99%能量或旧新颖性门槛筛结构。计算停止只表示实际预算结束，不表示维数收敛。

数值迭代次数、数据批次大小和资源预算须记录，但不能解释为结构维数。原专家自身训练时用过的组件数量也不转化为新学习器的控制上限。

## 今晚执行顺序

1. 完成完整空间数值验收。已完成三类方向FP64导数检查；完整问题Schur收敛仍在核对。
2. 核对八任务完整权重、任务头、共同基座和训练侧数据，建立来源清单。SUN397目前只有包含全部视觉参数的resume状态，必须如实标记，不冒称完成epoch08专家。
3. 构造按来源标记的需求流：专家功能变化、CE与类别/数据窗口需求。不把单个CE方向或8个初始方向直接叫作八任务低维结构。
4. 完整条件运动负责提供数学参照；控制器在后续需求上先尝试其已学联动，再用完整条件求解发现缺失运动。新结构要实际参与后续功能需求的求解，而不是事后PCA。
5. 在不参与结构学习的新需求窗口冻结控制器，检查目标响应、保护七任务响应、参数成本及与完整空间参照的差距。验证需求不得回灌同一窗口的结构。
6. 保存每任务已完成需求数、条件求解残差、控制秩/全部谱、参数参与关系、未完成项和耗时。未出现可分离块时不能把稠密向量硬叫成若干耦合块。

ODE次于真实结构学习；在线实际写回可后续进行；EC保持关闭。

## 当前真实状态

本文件是执行协议，不是八任务学习完成报告。`prepare.py`只做资源与完整坐标核验，并生成任务清单；不会用资源核验通过冒充控制结构学成。

现有八任务仍需通用多任务运行时和无固定维数控制学习器；数值验收未完成前，不把旧双任务代码直接循环八次当作一对七算法，也不把实验结果标记为八任务低维空间。

资源核验已完成8/8。`controls.py`已实现无容量上限的完整运动控制字典及新需求冻结验证接口，并在小问题上检查结构确实参与新需求解码；这只是软件实现，不是八任务结构已经学成。全部真实运动由独立完整条件求解器提供，不用该字典限制参照求解空间。
