# DTD trajectory and Fisher response data

`new_dtd_expert_geometry.json` is the original analysis output. `grams[anchor][task][image_group]` stores the complete 48×48 Gram for the DTD matrix atoms. The anchor keys are `base`, `dtd_expert`, and `sun_expert`. The task and anchor are separate dimensions. Each anchor uses the same two 32-image training probe groups for a given task. Matrix names and original update norms are stored in `matrix_names` and `matrix_norms`.

For atom \(i\), let \(a_i=\|\Delta\theta_i\|_F\) and \(u_i=\Delta\theta_i/a_i\). The columns of \(U\) occupy distinct parameter matrices for this single-expert analysis, so they are orthonormal up to numerical error. The response matrix is \(C=U^\top J^\top JU\), with \(J\) the derivative of the concatenated \(2\sqrt{p(x)}/\sqrt{n}\) embedding. For the actual matrix update, the diagonal energy is \(\sum_i a_i^2 C_{ii}\). Pair \(i<j\) contributes \(2a_i a_j C_{ij}\) to the full quadratic energy. The raw signed off-diagonal entries are present in every Gram matrix.

`dtd_geometry_top4.json` stores the four leading eigenvalues and a 48×4 matrix of eigenvectors, in descending order, fitted at the pretrained anchor on group A. Their group B explained response is \(\operatorname{tr}(V^\top C_B V)/\operatorname{tr}(C_B)=0.6849213243\). For each group separately, anchor similarity is the Frobenius cosine \(\langle C_{0},C_{8}\rangle_F/(\|C_{0}\|_F\|C_{8}\|_F)\). The measured values were 0.8237346460 and 0.5887910198. These quantities describe response energy within the candidate space. They do not estimate the dimension of the full visual encoder's parameter fiber.

`probability_trajectory.npz` stores arrays `probabilities[window, image_group, image, class]`, `epoch_step`, `epoch_checkpoints`, `raw_train_indices`, and `labels`. `trace.json` lists all 17 visual snapshots, from step 0 to step 216, and the nine epoch states. Window deltas are relative to the previous recorded step. Epoch deltas are relative to the previous epoch boundary. The epoch files include AdamW states, with an empty state before the first optimizer step. `comparison.json` records bitwise agreement of the replayed final visual tensors with the original expert. `trace_verified.json` records the verified window schedule and probability array shape.

The full snapshot and optimizer files listed in `trace.json` are under `results/DTD_DYNAMIC_TRACE_20261109/trace/` on the experiment server. Recreate them using `record_dtd_trajectory.py` with the original DTD best checkpoint as `--reference`. The DTD geometry can be recomputed with `analyze_dtd_expert_geometry.py --queue results/EXPERTS8_99_20261109 --output <file>`. These commands need the original pretrained weights, frozen heads, training split, and expert outputs.

## Eight-task response bank

The archive `eight_task_response.zip` contains the common pretrained anchor array `eight_task_base.npz` and one `at_<Task>.npz` for each expert anchor. Read `manifest.json` for ordering and train-only probe identities. For `eight_task_base.npz`, the `gram` axes are observing task, image group, candidate atom, candidate atom. There are eight observing tasks, two disjoint groups of 32 training images per task, and 384 atoms ordered by source expert and then by visual matrix. Every atom has unit parameter norm. The corresponding norms before normalization are in `atom_norms`. Atoms from different experts can overlap within a matrix, so the file also contains `atom_metric = U.T @ U`.

`candidate_coefficients` has 24 rows. Each task contributes its original 48-matrix update and two modes selected on group A by maximizing relative task response in the common parameter space. `summary.json` gives the row ordering, raw and normalized response energies on both image groups, and the checkpoint provenance. For each direction the two additional anchors are its source expert and the expert of the strongest other responding task on group A. At each anchor the smaller Gram arrays include all eight observing tasks, the same two image groups, and the candidates indexed by `candidate_indices`. `verified.json` records the matrix and direction checks.

These are local sensitivity measurements on training probes. The validation split and test split were not used for the response bank. Cars, DTD, and EuroSAT use expert checkpoints that passed a numerical proxy gate and still lack an original reference accuracy on the same validation split. Validation confirmation and finite-step protection of other tasks are separate from these sensitivity measurements.
